## Legend

| Value | Meaning |
|---|---|
| **Full** | The capability is implemented in this component and is the component's own responsibility. |
| **Partial** | The capability exists but is incomplete, narrower than a sibling's, or only covers part of the concern. |
| **Absent** | Read the source: the capability is demonstrably not implemented in this component. |
| **Unknown** | Cannot be determined from the repositories in scope (applies to `asbm-backend`, which has no repo). |

Finding labels: **[VERIFIED]** = read in source; **[INFERRED]** = reasoned, not directly confirmed.
Citations use the form `repo path:lines`. Repo short names: `appstore-metadata-service` (ASMS),
`appstore-bundle-service` (ASBS), `appstore-caching-service` (caching).

`asbm-backend` ("App Store Bundle Manager", name inferred) is an **external, unowned** dependency: it is
referenced only as an Nginx upstream and route target
(`appstore-caching-service appstore-caching-service-nginx/default.conf.template:24-26,50-87`) [VERIFIED].
Every `asbm-backend` cell is therefore **Unknown** unless the caching config itself proves something.

## Reading of the matrix

- Capability boundaries between ASMS and ASBS are clean at the *domain* level (rows 1–8): there is almost no
  functional duplication, only a client/server relationship [VERIFIED].
- Duplication is concentrated in the *cross-cutting* rows (15, 20, 22, 24, 25): correlation-ID filters,
  error normalisation, bundle-path derivation, and Helm/CI scaffolding are each implemented two or three
  times [VERIFIED]. These are the consolidation targets analysed in [08-fit-gap.md](08-fit-gap.md).
- Rows 13, 17, 21, 23 and the whole `asbm-backend` column are capabilities that **no in-scope repo owns**.
  See [08-fit-gap.md](08-fit-gap.md) §(d) and [10-open-questions.md](10-open-questions.md).
